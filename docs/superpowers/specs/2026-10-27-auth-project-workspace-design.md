# 登录、项目工作台与计算页入口设计

日期：2026-10-27
状态：已批准进入实现规划

## 目标

将当前直接打开计算器的 `apps/calc` 改造成完整的用户工作流：

1. 注册或登录。
2. 登录后进入项目工作台。
3. 在工作台新增、查询、修改、删除项目，并按状态查看进度。
4. 新建项目时必须选择地区，地区绑定在项目上。
5. 点击项目进入现有计算页；项目名称、地区和状态持续显示，并可返回工作台。

账号、项目和方案必须按用户隔离。现有脚手架计算能力、结果、图纸和计算书逻辑不重写。

## 范围与边界

### 本次实现

- 邮箱/密码注册、登录、退出和会话恢复。
- 用户级项目、方案和计算记录隔离。
- 项目工作台、项目 CRUD、搜索、状态筛选。
- 项目地区、状态、方案数和最近计算时间。
- 项目 → 现有计算页的导航和上下文保留。
- 移动端可用布局、键盘操作、错误与空状态。
- 后端与浏览器端完整验收。

### 不在本次实现

- 地区不切换计算规范，不改变现有模块公式或参数。
- 不实现管理员后台、角色权限、团队共享或组织管理。
- 不实现邮件验证、找回密码、第三方登录。
- 不实现方案版本历史、附件或审批流。
- 不把项目状态自动推断为“已完成”；状态由用户明确选择。

## 信息架构

### 路由

- `/login`：登录页。
- `/register`：注册页。
- `/workspace`：登录后的项目工作台。
- `/projects/:projectId/calc`：指定项目的现有计算工作区。
- `/`：已登录跳转 `/workspace`，未登录跳转 `/login`。

未登录访问受保护路由时跳转 `/login?next=<原路径>`。登录成功优先返回安全的站内 `next`，否则进入 `/workspace`。

### 页面流

```text
注册 / 登录
    ↓
项目工作台
    ├─ 新建项目 → 创建并进入计算页
    ├─ 点击项目 → 计算页
    ├─ 编辑项目 → 保存后停留工作台
    └─ 删除项目 → 二次确认 → 工作台
```

## 认证与会话

### 账号模型

使用 Django 内置 `User`，不新增自定义用户表：

- 以规范化小写邮箱作为 `username` 和 `email`。
- 注册时同时校验邮箱大小写不敏感唯一性。
- 前端注册字段：邮箱、密码、确认密码。
- 使用 Django 密码哈希和密码强度校验。
- 首个注册用户不自动获得全局管理权限；当前所有注册用户地位相同。

开放注册，不设置邀请码。账号登录后只能看到本人创建的数据。

### 会话

- 使用 Django Session Cookie，不把会话 Token 暴露给 JavaScript。
- Cookie 使用 `HttpOnly`、`SameSite=Lax`；生产环境启用 `Secure`。
- 修改类请求使用 CSRF Token。
- 登录、退出和注册完成后轮换会话。
- 页面刷新通过 `/api/v1/auth/me` 恢复当前用户。
- 未认证 API 返回 HTTP 401；前端收到 401 时清理 Query 缓存并跳转登录页。

### 开发同源策略

Vite 开发服务器代理 `/api` 到 Django `127.0.0.1:8001`，浏览器仍视为同源。生产部署也通过同域反向代理暴露 `/api`，避免跨域凭证 Cookie。

## 数据模型

### CalcRun

新增：

- `owner`：外键到 `AUTH_USER_MODEL`，必填，`on_delete=CASCADE`，建立索引。

运行记录列表、详情都只返回 `owner=request.user` 的记录。创建 run 时写入当前用户。

### ScaffoldProject

新增：

- `owner`：外键到 `AUTH_USER_MODEL`，必填，`on_delete=CASCADE`，建立索引。
- `region`：必填文本，候选值固定为：
  - 全国
  - 上海
  - 江苏
  - 浙江
  - 北京
  - 山东
  - 广东
  - 湖北
  - 福建
  - 重庆
- `status`：必填枚举，默认 `preparing`：
  - `preparing`：筹备中
  - `calculating`：计算中
  - `completed`：已完成

现有 `name`、`code`、`client`、`location`、`designer`、`note` 保留。地区只作项目字段，不参与当前计算内核选择。

### ScaffoldScheme

不新增独立 owner；归属由 `project.owner` 决定。所有方案查询、创建、修改和删除均先校验当前用户拥有所属项目。

### 进度派生

项目不保存手填百分比。项目 API 返回：

- `scheme_count`：项目方案数。
- `last_calculated_at`：项目方案最近一次关联 `last_run.created_at`；没有计算时为空。
- `failed_control_count`：所有方案最近 run 中控制项失败数之和；无 run 按 0 计。

工作台进度由状态、方案数和最近计算时间共同表达。

### 历史数据迁移

现有无 owner 数据需要通过迁移保留。迁移创建一个不可登录的 `legacy-data` 系统用户作为历史数据所有者；该用户没有可用密码，不授予管理权限。普通用户不会看到历史数据。

## API 契约

### 认证

- `GET /api/v1/auth/csrf`：设置并返回 CSRF Cookie 状态（响应体不含 Token）。
- `POST /api/v1/auth/register`
  - body：`email`、`password`、`password_confirm`
  - 成功：201，设置会话，返回当前用户。
- `POST /api/v1/auth/login`
  - body：`email`、`password`
  - 成功：200，设置会话，返回当前用户。
- `POST /api/v1/auth/logout`
  - 成功：204，清空会话。
- `GET /api/v1/auth/me`
  - 已登录：200，返回 `user_id`、`email`、`display_name`。
  - 未登录：401。

### 项目

- `GET /api/v1/projects`
  - query：`search`、`status`、`limit`
  - 只返回当前用户项目。
- `POST /api/v1/projects`
  - 必填：`name`、`region`、`status`（默认 `preparing`）。
  - 返回派生进度字段。
- `GET /api/v1/projects/:id`
  - 只允许 owner 访问；其他用户返回 404。
- `PATCH /api/v1/projects/:id`
  - 可修改名称、编号、地区、状态、建设单位、地点、设计人、说明。
- `DELETE /api/v1/projects/:id`
  - 只允许 owner 删除；级联删除方案。

### 计算、方案和导出

除认证端点外，所有现有 `/api/v1/*` 端点都要求登录。

- run 列表只返回本人记录。
- run 创建写入 owner。
- 方案的所属项目必须是当前用户所有。
- geometry、report、DXF、PNG、batch 和导出端点要求认证，但不额外保存项目数据。

## 前端结构

### 路由与状态

- 新增 React Router，使用 BrowserRouter。
- 新增 `AuthGate`：基于 TanStack Query 的 `/auth/me` 判断会话。
- 服务器状态全部通过 TanStack Query 管理；不把用户、项目或方案复制进 Zustand。
- Query key：
  - `['auth','me']`
  - `['projects', filters]`
  - `['project', projectId]`
  - `['schemes', projectId]`

### 页面组件

- `LoginPage`
- `RegisterPage`
- `WorkspacePage`
- `ProjectTable`
- `ProjectFormDialog`
- `StatusBadge`
- `CalcWorkspacePage`
- `UserMenu`

现有 `App.tsx` 的计算工作区拆成 `CalcWorkspacePage`。原模块树、参数、画布、结果和导出逻辑保持不变。

### 登录页与注册页

采用左右分栏：

- 左侧深墨绿工程网格品牌区，显示产品定位和三项简短能力说明。
- 右侧为登录或注册表单。
- 小于 820px 时合并为单列，品牌区压缩为顶部品牌头。
- 表单使用明确 label、错误摘要、字段错误和提交中状态。
- 登录页提供“创建账号”，注册页提供“返回登录”。

### 项目工作台

采用视觉确认的 A 方案：

- 顶部：品牌、项目工作台、最近计算、用户菜单。
- 标题区：项目工作台说明和“新建项目”主按钮。
- 指标区：全部项目、计算中、计算方案、已完成。
- 工具栏：搜索、状态标签筛选、刷新。
- 项目表列：
  - 项目名称与编号
  - 地区
  - 状态
  - 方案数
  - 最近计算时间
  - 更新时间
  - 进入/更多操作
- 点击项目行或“进入计算”打开 `/projects/:projectId/calc`。
- “更多”菜单提供编辑和删除。
- 删除必须二次确认，说明会级联删除方案。
- 搜索无结果和完全没有项目使用不同空状态。
- 加载时使用稳定骨架行，错误时提供重试。

### 新建项目

新建对话框字段：

- 项目名称，必填。
- 项目地区，必选，默认“全国”。
- 项目状态，默认“筹备中”。
- 项目编号、建设单位、项目地点、设计人、项目说明可选。

主操作“创建并进入”成功后直接进入新项目计算页；次操作“仅创建”成功后停留工作台。

地区字段旁提示：“地区随项目保存，当前计算规则暂不随地区切换。”

### 编辑项目

使用相同表单与校验。保存后更新项目缓存并停留工作台。若修改地区，只更新项目显示，不改变已有方案参数或计算结果。

### 计算页

在现有计算器上方增加项目上下文条：

- 返回项目工作台。
- 项目名称、地区、状态。
- 当前项目方案数。

现有 TopBar 不再承担项目选择。方案入口只管理当前项目的方案：

- 列出当前项目方案。
- 保存当前参数为新方案。
- 打开历史方案。
- 删除当前项目方案。

不再从计算页新建项目或切换到其他项目；项目切换统一从工作台进入。

## 视觉与交互

- 延续当前深灰工程控制台风格，项目工作台使用白/浅灰背景和墨绿主操作色。
- 状态颜色只表达状态，不承担唯一信息：筹备中=琥珀，计算中=墨绿，已完成=蓝灰。
- 项目行支持键盘 Enter 打开。
- 所有菜单和对话框支持 Escape 关闭与焦点返回。
- Motion 只用于页面进入、对话框和行状态变化，并尊重 `prefers-reduced-motion`。
- 不使用冻结表格、横向无限滚动或隐藏关键列。

## 错误处理

- 注册邮箱已存在：字段级错误。
- 密码弱或确认不一致：字段级错误。
- 登录失败不泄露“邮箱是否存在”。
- 项目不存在或属于其他用户：404。
- 项目名称或地区缺失：400，字段级展示。
- 会话过期：关闭当前对话框，跳转登录并保留站内 next。
- 删除失败：保留工作台数据，显示可重试错误。
- 计算页项目加载失败：显示返回工作台按钮，不进入无项目上下文的计算器。

## 测试与验收

### 后端

- 注册、重复邮箱、弱密码、登录、退出、me。
- 未登录 API 401。
- 注册后自动登录并建立会话。
- 项目 owner 隔离；跨用户读取、修改、删除返回 404。
- 项目 region/status 校验和默认值。
- 项目派生 scheme_count、last_calculated_at、failed_control_count。
- 方案和 run 的 owner 隔离。
- 历史数据迁移幂等且不向普通用户暴露。

### 前端

- 登录、注册、字段错误和 next 跳转。
- 未登录访问重定向，登录后刷新保持会话。
- 工作台统计、搜索、状态筛选、空状态、错误状态。
- 新建项目必须选择地区。
- 创建并进入正确项目计算页。
- 编辑项目、删除确认和删除后刷新。
- 点击项目行键盘可打开。
- 计算页显示项目上下文；返回工作台。
- 方案保存与打开只作用于当前项目。

### 浏览器验收

使用真实 Chromium：

1. 注册新用户。
2. 创建上海项目。
3. 搜索并编辑项目状态。
4. 进入计算页，保存方案并刷新恢复。
5. 返回工作台，确认方案数和最近计算时间变化。
6. 删除测试项目。
7. 用第二个账号注册并确认看不到第一个账号的数据。
8. 检查无控制台错误、无 4xx 未处理、无移动端横向溢出。

## 交付边界

- 完成后现有 10 个脚手架模块仍保持当前计算行为和 `verified` 状态。
- 地区字段只是项目属性，不宣称已实现地方规范切换。
- 账号功能不代表商业级身份系统；邮件验证、找回密码和组织权限明确留待后续。
