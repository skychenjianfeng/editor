# 玄构天枢品牌与本地演示登录设计

状态：已批准

## 目标

1. 将计算应用的产品品牌统一为“玄构天枢”。
2. 本地开发时，登录页默认填入一个可用的演示账号和密码，减少重复输入。
3. 生产构建不得包含默认账号或密码。

## 品牌替换

- 登录页、注册页侧栏品牌：`PM STUDIO` 改为“玄构天枢”。
- 标志方块文字：`PM` 改为“玄”。
- 工作台顶栏品牌：`PM STUDIO` 改为“玄构天枢”。
- 计算页顶栏产品名：“安全计算工作台”改为“玄构天枢”。
- 浏览器标题：改为“玄构天枢 · 结构与脚手架安全计算”。
- favicon 中的 `PM` 改为“玄”。
- 不修改项目编号（如 `PM-018`）、“品茗”计算方法名称或其它业务专有内容。

## 本地演示登录

### 配置

新增前端环境变量：

```text
VITE_DEV_LOGIN_EMAIL=
VITE_DEV_LOGIN_PASSWORD=
```

- `apps/calc/.env.example` 只保留空值和说明，不提交真实凭据。
- 实际值写入被 Git 忽略的 `apps/calc/.env.local`。
- 仅当 `import.meta.env.DEV === true` 且两个变量都非空时，登录表单使用它们作为默认值。
- 任一变量为空、或处于生产构建时，邮箱和密码默认值均为空字符串。

### 演示账号

- 在当前默认 Django SQLite 数据库创建一个本地演示用户。
- 账号与密码从同一组本地环境变量读取，避免源码和文档出现真实密码。
- 账号使用普通用户权限，不授予管理员或超级用户权限。

### 页面行为

- 登录页打开后自动填充邮箱和密码，用户可直接点击“登录”。
- 用户仍可修改或清空字段。
- 不新增凭据展示、复制按钮或“演示账号”提示，避免扩大信息暴露。
- 现有登录、CSRF、会话和安全校验逻辑不变。

## 错误处理

- 环境变量缺失时静默使用空表单，不报错、不阻塞页面。
- 演示账号创建失败时停止实施并报告，不把空账号或无效密码写入环境文件。
- 登录失败继续使用现有统一错误提示。

## 测试

- 单元测试覆盖开发环境有配置时预填、生产环境不预填、配置缺失时不预填。
- 品牌测试覆盖登录页、工作台和计算页显示“玄构天枢”。
- `npm --prefix apps/calc test`
- `npm --prefix apps/calc run check-types`
- `npm --prefix apps/calc run build`
- 真实 Chrome 检查登录页默认值与直接登录成功。

## 非目标

- 不在生产环境提供默认账号。
- 不修改认证 API、用户隔离、CSRF 或会话策略。
- 不改变计算公式、结果、图纸或 `verified` 状态。

## 回滚

- 删除两个本地演示登录变量及对应默认值逻辑，即可恢复空表单。
- 品牌改动可按提交单独回滚，不影响数据库结构和计算数据。
